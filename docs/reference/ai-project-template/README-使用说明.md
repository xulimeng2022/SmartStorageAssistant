# AI 开发项目 Obsidian 通用模板

这是一套面向小型 AI 开发项目的知识库模板。它把项目管理拆为：

1. 先确认客户问题、功能边界和交付结果。
2. 再建立架构、模块和数据流。
3. 把实现拆成可以独立验收的小任务。
4. 每个任务先写测试，再实现，再记录验收结果。

## 新项目使用顺序

1. 复制整个模板文件夹，并将文件夹改名为「项目名称」。
2. 先填写 [[01-需求与范围确认]]，与客户确认后再进入开发。
3. 填写 [[00-项目索引]] 和 [[02-系统架构]]。
4. 每个模块从 [[03-模块文档-模板]] 复制一份，按「模块名」命名。
5. 从 [[04-任务与验收清单]] 建立项目待办；每个开发窗口只领取一个任务。
6. 开发前复制 [[05-单任务卡-TDD]]，先让测试描述预期行为。
7. 需要让 AI 建立项目资料时，使用 [[06-AI新项目启动提示词]]。

## 笔记保存原则

- 项目索引：只保存项目定位、入口和当前阶段。
- 架构：只保存稳定的系统分层、模块边界和依赖关系。
- 模块笔记：只保存该模块的职责、接口、状态、排查入口和长期决策。
- Todo：保存可执行任务和验收项。
- 当前任务卡：保存本次改动、测试结果和临时排查记录；任务结束后只将长期结论回写到架构、模块或 Todo。

> [!warning] 不要把敏感数据写入知识库
> 账号密码、客户真实数据、访问令牌、完整日志、截图、接口响应和未脱敏导出文件，应保留在受控位置或当前任务中，不要进入同步笔记库或代码仓库。

## 与 AI 协作的最小规则

- 开发前：只提供当前任务需要的索引、架构、对应模块和验收标准。
- 开发中：一个对话或窗口只处理一个明确功能或一个 Bug。
- 需求不明确：要求 AI 先列出待确认项，不让它猜测。
- 修改前：先写会失败的测试，再实现最小代码使测试通过。
- 完成后：更新任务状态；只有稳定的设计结论才回写到知识库。
