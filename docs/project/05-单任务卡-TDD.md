# 单任务卡模板（TDD）

> 用法：重要任务（Level 2/3，见 [README-使用说明](README-使用说明.md)）开始前复制本模板到 `tasks/`，按 `T-编号-简短名称.md` 命名，并在 [04-任务与验收清单](04-任务与验收清单.md) 登记。
> 本文件保持空白模板，不填具体任务。

# T-000-任务名称

## 任务边界
- 所属模块：[modules/](modules/)（链接对应模块文档）
- 对应需求/验收：[01-需求与范围确认](01-需求与范围确认.md)（F-编号/A-编号）
- 目标行为：【完成后用户/系统可观察变化，一句话】
- 本任务不做：【明确排除的功能/重构/顺手修改】
- 前置依赖：【已完成任务/接口/无】

> 开始前检查：目标行为、输入输出、验收方式或依赖任一项不明确 → 先回需求/模块文档补充，标「待确认」，不让实现者猜。

## 验收示例
### 正常路径
- 给定：【前置状态/输入】
- 当：【操作/事件】
- 则：【预期可观察结果】
### 异常或边界路径
- 给定：【前置状态/输入】
- 当：【操作/事件】
- 则：【预期错误状态/提示/人工处理】

## TDD 记录
### 1. 失败测试
- 测试文件/名称：【路径/名称】
- 描述的行为：【一句话】
- 首次失败原因：【尚未实现/当前行为不符】

### 2. 最小实现
- 拟修改文件：【路径】
- 最小改动说明：【只说明满足本任务的改动】
- 不新增的复杂度：【暂不抽象/暂不重试，原因】

### 3. 验证结果
| 验证项 | 结果 | 证据 |
| --- | --- | --- |
| 新增/修改测试 | 通过/失败 | 测试名或命令 |
| 受影响相关测试 | 通过/失败 | 测试名或命令 |
| 手工验收（若需要） | 通过/不适用 | 简短操作与结果 |

## 实施日志（短期，任务结束不保留到长期文档）
- 【YYYY-MM-DD】：【做了什么、发现什么】

## 完成结论
- 状态：【待开始/进行中/阻塞/已验收】
- 交付结果：【代码/文件/接口简短说明】
- 需要回写的长期事实：【要更新的模块文档/架构/Todo；无则写「无」】
- 后续任务：【T-编号/无】

> 任务完成后：稳定结论回写模块文档；一次性日志、完整终端输出、真实数据、截图不写入长期知识库。
