# 智能收纳助手 · 系统架构

> 来源：代码结构（`app/src/main/java/com/example/smartstorage`）、gradle 配置、AGENTS.md(v1.1.0)。只画真实存在的组件；不存在服务端/账号/云同步。
> 模板原文见 `../reference/ai-project-template/02-系统架构.md`。

## 设计目标与约束

- 核心目标：单机、轻量、离线优先的物品位置记录；AI 解析仅为可选增强。
- 使用边界：Android 8.0+（minSdk 26），单模块 `:app`，纯本地 + 可选外部 LLM 文本解析。
- 关键约束：无服务端、无账号体系；数据/照片不离开本机（除用户主动调用 LLM 时发送口述文本）；Release 需混淆与签名。
- 关联需求：[01-需求与范围确认](01-需求与范围确认.md)

## 系统概览

~~~mermaid
flowchart LR
    User[用户] --> UI[Compose UI<br/>MainScreen + 各页面]
    UI --> VM[ViewModel<br/>presentation/*]
    VM --> UC[UseCase<br/>domain/usecase]
    UC --> Repo[ItemRepository 接口<br/>domain/repository]
    Repo --> Impl[ItemRepositoryImpl<br/>data/repository]
    Impl --> Room[(Room items 表)]
    Impl --> Img[ImageStorage<br/>filesDir/item_images]
    UC --> LLM[LlmClient<br/>data/remote/llm]
    LLM --> Transport[OkHttpLlmTransport]
    Transport --> Ext[OpenAI 兼容 LLM 服务]
    VM --> Prefs[DataStore / 加密存储<br/>data/local/prefs]
    VM --> Backup[BackupRepository<br/>ZIP 导出/导入]
~~~

> 注：UI 与 UseCase/数据之间一律经 ViewModel；Repository 对上层隐藏 Room/文件细节；LLM 失败自动降级本地规则，不阻塞主流程。

## 模块边界

| 层/模块 | 负责什么 | 不负责什么 | 对外输入/输出 | 依赖 |
| --- | --- | --- | --- | --- |
| presentation | 页面、导航、用户输入、状态展示 | 业务规则、持久化、网络 | 用户操作 → UI 状态/事件 | domain + data(local.prefs) |
| domain | 模型、仓库接口、用例（业务编排） | Android 依赖、持久化、网络实现 | 用例输入 → 结果/Flow | 无 Android 依赖（可单测） |

| data.remote.llm | OpenAI 兼容调用、错误分类、本地降级解析 | 其它网络 | 文本 → ParsedItem 列表 | OkHttp |
| di | Hilt 装配（DB/Repository/Remote） | 业务逻辑 | 依赖图 | 各层 |

## 主数据流

### 流程：单条/批量添加（经 AI 解析）
1. 输入来自添加页（文本或键盘语音整句）。
2. AddItemViewModel 调 LlmClient.parseItem / parseItems（模型失败自动本地规则降级，经 ParsedItemSanitizer 统一清洗）。
3. 解析结果进入工作副本（可编辑）；照片经 ImageStorage 压缩入库前不落库。
4. 保存时：单条走 AddItemUseCase（先 GetItemByNameUseCase 查重，重名弹窗决策）；批量走 BatchAddItemsUseCase（逐条、单条失败不中断、照片路径互斥/复制）。
5. 成功后经 Flow 自动刷新首页；StarMilestoneRepository.incrementTotalAdded 计数。

### 流程：搜索
1. 首页输入关键词 → SearchItemsUseCase（去空白 → 逐字 `%…%` LIKE，含反向包含）；空白等价观察全部。
2. AI 语义搜索：LlmClient 把整句解析为名称/地点/描述 → SearchItemsByFieldsUseCase 三字段精确筛选（空字段不限）。
3. 结果按 updated_at 倒序展示；用 observeActiveCount 区分「从未添加」与「搜索无结果」。

### 流程：回收站
1. DeleteItemUseCase 软删除（只写 deleted_at，数据与照片保留）。
2. Trash 页 RestoreItemUseCase 恢复 / PermanentDeleteItemUseCase 永久删除（先删照片再物理删记录）/ EmptyTrashUseCase 清空。
3. 所有物理删除路径均先 `ImageStorage.deleteImage` 清理文件。

### 流程：备份
1. BackupRepository.exportData：全部物品（含回收站）→ data.json + images/ 打包 ZIP 到用户所选 Uri；附带 textColorConfig。
2. importData：OVERWRITE=清空库与照片后导入（保留原 ID）；MERGE=按名称忽略大小写去重，重名跳过，其余自增插入；图片解压到 item_images（防冲突命名）。

## 技术选型

| 层级 | 选择 | 说明/已知限制 |
| --- | --- | --- |
| 语言 | Kotlin 2.0.21（100%） | KSP1 |
| UI | Jetpack Compose + Material3（BOM 2024.12.01）+ icons-extended | 自定义底部栏（固定 64dp）规避 M3 高度测量异常 |
| 架构 | MVVM + Clean（UseCase + Repository 接口） | 表现层不直连数据 |
| 数据库 | Room 2.6.1（version 4，显式迁移 v1→v4，失败兜底破坏性重建） | 单表 items |
| DI | Hilt 2.52 + hilt-navigation-compose | |
| 异步 | Coroutines + Flow | |
| 网络 | OkHttp 4.12.0（连接 7s / 读 25s / 写 7s） | 仅 LLM |
| 存储 | DataStore Preferences + EncryptedSharedPreferences(security-crypto 1.0) | Key AES-256-GCM 加密 |
| 图片 | Coil 2.7.0 + 自研 ImageStorage | 1080px 宽 / JPEG 80 / EXIF 修正 |
| 测试 | JUnit4；单元测试 6 文件 | 无 androidTest |
| 路由 | 自定义 sealed Screen + HorizontalPager + 覆盖层 | 未用 NavHost |

## 接口与数据所有权

| 数据/接口 | 所有者 | 写入者 | 读取者 | 校验/边界 | 敏感级别 |
| --- | --- | --- | --- | --- | --- |
| items 表 | data.local | Repository/DAO | Repository→VM | 软删除过滤在 DAO 查询 | 本地私有 |
| 照片文件 | ImageStorage | 保存/物理删除时 | Coil 展示 | 绝对路径入 JSON 数组 | 本地私有 |
| API Key | SettingsRepository | 用户/构建注入 | LlmClient | EncryptedSharedPreferences；免费 Key 仅 BuildConfig | 敏感（禁止入库/日志） |
| AI 设置 | SettingsRepository | 用户 | LlmClient/设置页 | DataStore ai_settings | 内部 |
| 备份 ZIP | 用户 | BackupRepository | BackupRepository | 版本号 BACKUP_VERSION=1.0 校验 | 含本地数据，用户自管 |
