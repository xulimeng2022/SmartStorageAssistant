# M05 备份与恢复

## 1. 职责与边界

### 模块职责
- 导出全部物品（含回收站）与图片为 ZIP（`data.json` + `images/`），附带全局文字颜色配置。
- 导入备份：解析预览信息、版本校验；支持覆盖（清空后导入）与合并（按名称去重）两种模式。

### 不负责什么
- 不做云备份/自动备份调度；不处理备份文件的上传分享。
- 不含 LLM/偏好设置（AI 配置、语言、主题模式不备份，仅备份文字颜色配置）。

### 上下游关系
| 方向 | 模块 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | M11 设置页 | 用户选择 Uri（SAF） | 导入前先 parseBackupInfo 预览 |
| 输出 | 用户文件系统 | ZIP | data.json + images/ |
| 依赖 | M01 DAO、M06 ThemeRepository | 物品/文字颜色 | - |

## 3. 核心流程
### 导出
1. `getAllItems()`（含回收站）→ 原路径映射为 ZIP 内 `images/item_<id>_<序号>_<hash>.<ext>`。
2. 写 `data.json`（version=1.1、exportTime、items、textColorConfig、aiIndexes）+ 逐文件写入 images/；图片缺失跳过。
3. `aiIndexes` 只导出正常物品（非回收站）的 `SUCCESS` 索引；回收站物品的图片仍备份但不导出索引。
### 导入
1. 单次流式读取 ZIP，`data.json` 解析到内存，图片先解压到 cache 暂存目录；版本必须属于 `SUPPORTED_BACKUP_VERSIONS`（`1.0` 或 `BACKUP_VERSION="1.1"`），否则拒绝。
2. 暂存图片复制到 `filesDir/item_images` 前先登记目标文件；复制中断留下的半写残片也进入清理范围，清理失败不覆盖原始导入错误。
3. OVERWRITE / MERGE 与索引恢复在同一 Room 事务内完成；OVERWRITE 保留备份原 ID，MERGE 按 `findByNameIgnoreCase` 跳过重名项。
4. 事务提交边界使用 `NonCancellable` 保护；父协程随后取消时仍向上传播取消，但不会把已提交数据库引用的新图片当失败产物删除。
5. 导入收口后重新查询数据库最终引用集合，只删除本次新增且未引用的文件；MERGE 跳过项独占的图片会清理，被其他导入项共享的图片会保留。数据库引用无法确认时保守保留。
6. 备份含文字颜色配置时恢复（ThemeRepository.saveTextColorConfig）。
7. 1.1 备份的 `aiIndexes` 按 itemId / imagePath 映射重建为 `SUCCESS` 索引；1.0 备份没有索引，不自动上传，由用户主动建立。

## 4. 数据与接口
- `BACKUP_VERSION = "1.1"`（`SUPPORTED_BACKUP_VERSIONS = {"1.0", "1.1"}`）；`data.json` items 字段含 imagePaths（ZIP 相对路径）与 deletedAt 空值语义（JSONObject.NULL），可选 `aiIndexes` 数组。
- ImportMode：OVERWRITE / MERGE。
- 结果统计：ImportResult(totalItems/importedItems/skippedItems/failedItems)、ExportResult(itemCount)。

## 5. 状态、错误与排查
| 情况 | 处理 | 排查 |
| --- | --- | --- |
| 版本不兼容/缺 data.json | 抛 IllegalArgumentException，UI 提示 | 备份来源/文件完整性 |
| 单条导入失败 | failed++ 继续 | 名称/图片缺失 |
| 无法打开输出 Uri | 抛 IllegalStateException | SAF 授权 |
| 导入取消/失败 | 事务未提交时清理本次新文件；已提交时仅按数据库引用清理未引用项 | BackupRepository / Room 事务日志 |

## 9. T-011：覆盖导入安全

- 导入先流式解压到暂存目录并完整解析，再将图片写入正式目录，最后在 Room 事务内覆盖/合并写入。
- 数据库事务失败时回滚并删除本次新文件，不再先清空旧数据；提交成功后才清理覆盖前旧图片。
