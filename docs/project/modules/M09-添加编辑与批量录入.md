# M09 添加 / 编辑与批量录入

## 1. 职责与边界

### 模块职责
- 新增与编辑物品的统一表单（工作副本模型），语音/键盘输入 + AI 解析回填 + 多图管理。
- 保存流程：单条重复检测弹窗（更新旧记录/新建/取消）；批量草稿勾选保存（含照片归属）。
- 未保存修改离开时的确认与丢弃；保存成功触发 Star 里程碑计数。

### 不负责什么
- 不直接写数据库（经 M02 用例 + M01 仓库）；不做首页/详情/回收站展示。

### 上下游关系
| 方向 | 模块 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | 用户/键盘语音 | 口述文本/表单/照片 | ItemEditState 工作副本 |
| 输出 | M02 用例（Add/Update/GetItemByName/BatchAdd） | Item / drafts | 保存时才提交 |
| 依赖 | M03 LlmClient、M04 ImageStorage、M06 Star/Theme、M12 对话框 | 解析/图片/里程碑/文字颜色/失败引导 | - |

## 3. 核心流程
1. 进入页面：编辑则从库复制 Item → ItemEditState；新增为空（id=0）。UI 唯一数据源为 ItemEditState。
2. AI 解析：口述文本 → parseItems（来源 MODEL/LOCAL_FALLBACK）；失败/超时 → AiParseFailedDialog 两出口（去配置/稍后），「稍后」自动本地降级并保留结果继续填写。
3. 保存：单条按名称查重 → 无重名直接 AddItemUseCase；有重名弹 DuplicateCheckState，用户选 UPDATE_EXISTING / INSERT_NEW / CANCEL。
4. 批量：BatchAddItemsUseCase.execute(drafts, selected, resolveDuplicate, copyFile)；结果 BatchAddOutcome，失败 uid 保留重试。
5. 提交成功：删除本次移除图片文件（仅编辑时）→ 返回并触发 Star 检查。

| MAX_IMAGES | 9（companion object） |

## 5. 状态、错误与排查
| 情况 | 处理 |
| --- | --- |
| AI 失败/超时 | AiParseFailedDialog；稍后→本地降级并保留输入 |
| 保存遇重名 | 弹窗三选一 |
| 批量部分失败（名称空/异常） | failedUids 保留重试 |
| 照片读取失败 | 提示，不阻塞手动填写 |
| 未保存离开 | 弹确认，确认后丢弃工作副本 |
