# M01 本地数据与仓库

## 1. 职责与边界

### 模块职责
- 维护物品的唯一持久化数据源：Room `items` 表、DAO 查询、v1→v4 显式迁移、类型转换。
- 实现 `ItemRepository` 接口：观察/搜索/增删改/回收站，并把「领域对象 ↔ 实体」互转。
- 生成逐字模糊搜索的 LIKE 模式（`SearchPattern`）。

### 不负责什么
- 不包含业务用例编排（见 M02）、AI 解析（M03）、图片文件读写（M04）、备份打包（M05）、偏好存储（M06）。
- 不做页面状态管理。

### 上下游关系
| 方向 | 模块 | 交换内容 | 约定 |
| --- | --- | --- | --- |
| 输入 | domain（M02） | Item / 仓库接口调用 | 领域模型，无 Android 类型 |
| 输出 | presentation（M08~M10） | Flow<List<Item>> 等 | 经 UseCase 间接消费 |
| 依赖 | ImageStorage（M04） | 物理删除时清理照片 | 永久删除/清空前先删文件 |

## 3. 核心流程
### 搜索
1. `ItemRepositoryImpl.searchItems`：trim；空关键字直接返回全部（避免 `LIKE '%%'`）。
2. 去掉所有空白 → `buildFuzzyLikePattern` 生成 `%x%y%z%`（转义 `% _ \`）。
3. `ItemDao.searchFuzzy`：命中 name/location/description 任一，另保留“反向包含”（关键词包含存储值）；`ORDER BY updated_at DESC`。

### 回收站（物理删除前先清照片）
1. `permanentDeleteItem`：先 `imagePaths.forEach { imageStorage.deleteImage(it) }`，再 `dao.permanentDelete(id)`。
2. `emptyTrash`：先取全部已删记录清理照片，再 `permanentDeleteAll()`。

## 4. 数据与接口
### items 表字段
id(Long 自增)/name/location/description/image_path(JSON 数组文本)/created_at/updated_at/deleted_at(null=正常)。迁移：v1→v2 加 image_path；v2→v3 加 deleted_at；v3→v4 单图字符串包装为 JSON 数组；`fallbackToDestructiveMigration()` 兜底。

### 关键接口
| 名称 | 调用方 | 输入 | 成功输出 | 失败输出 |
| --- | --- | --- | --- | --- |
| ItemRepository.observeItems/searchItems/... | domain UseCase | 见上 | Flow<List<Item>> | Flow 异常 |
| ItemDao.getItemByName | Repository | name | ItemEntity? | - |
| ItemDao.searchFuzzy | Repository | pattern, normalized | Flow | - |

## 5. 状态、错误与排查
| 状态/错误 | 触发 | 用户可见结果 | 系统行为 | 优先排查 |
| --- | --- | --- | --- | --- |
| 迁移失败 | 旧库无法按显式迁移升级 | （罕见） | 破坏性重建（数据丢失） | AppDatabase + DatabaseModule |
| 搜索转义 | 关键词含 % _ \ | 正常命中字面量 | 模式转义 | SearchPattern.kt |
| 英文大小写 | 搜索/查重 | 忽略大小写 | SQLite LOWER/LIKE | DAO 查询 |
