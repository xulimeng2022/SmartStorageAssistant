## Required Fixes

### 行为规则

- `allAssigned`：当前批量草稿全部 `photoPaths` 的精确路径集合。
- `unassigned`：`ItemEditState.currentImagePaths` 中不属于 `allAssigned` 的路径，保持照片池原顺序。
- `availablePhotoPaths`：`选中草稿的精确照片并集 + unassigned`，按绝对路径去重，保持“选中草稿照片在前、未分配照片按池顺序在后”。
- `selectedPhotoPaths` 默认值：仅选中草稿原有照片并集，不默认选中未分配照片。
- 仅属于未选中草稿的已分配照片不得进入候选。
- 候选列表不截断；既有单件 9 张上限继续约束勾选和确认。
- 取消仅关闭预览，不改变草稿、照片池或文件；重新打开时仍可看到候选。
- 确认只替换选中草稿为一个合并草稿。未选照片和未参与草稿保持原规则，不提前删除文件或产生重复关联。

### 最小实现

- 新建 UI-owned 纯函数策略文件，例如 `presentation/add/BatchMergePhotoPolicy.kt`。
- 可定义 `internal data class BatchMergePhotoCandidates`，同时返回可选项与默认选中项。
- `AddItemViewModel.startBatchMerge()` 必须把全部草稿路径和 `_editState.value.currentImagePaths` 传入策略，不再把 `merged.photoPaths` 同时当作可选项和默认选中项。
- UI 行展示使用路径，不得使用文件名作为去重键。
