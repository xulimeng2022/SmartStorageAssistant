## Required Fixes

### DATA-1（BLOCKER）导入事务提交后取消不得删除已引用图片

- `BackupRepository` 中不能在事务成功提交后因父协程取消而进入“未提交”清理分支。
- 明确区分 `CancellationException`、事务提交成功和真实失败；只有确认数据库未引用本次新文件时才允许删除。
- 增加提交/取消边界回归测试；无法运行 Android 测试时至少提供可编译的测试 seam 和确定性证据。

### DATA-2（IMPORTANT）MERGE 跳过重名物品时清理未引用图片

- 暂存图片若最终没有任何数据库引用，必须在成功或失败收口后删除。
- 不得删除既有物品引用的文件，不得因合并跳过一条物品而误删仍被其他导入项引用的文件。
- 增加“同名被跳过 + 多物品共享图片”的测试。

### DATA-3（IMPORTANT）完全删除必须反映真实删除结果

- `deleteRecursively()`、`File.delete()`、`SharedPreferences.commit()` 等布尔结果不得静默忽略。
- `ResetReport` 的 `filesCleared` / `preferencesCleared` 必须反映实际失败；失败时 ViewModel 不得报告完全成功。
- 验证不触碰系统相册、外部备份和其他应用数据。
- 增加失败分支测试或可执行 seam。

### DATA-4（IMPORTANT）软删除物品不得继续进入图片索引队列

- `getQueued()` 不得返回已软删除物品的索引行；优先在 Data DAO/Repository 查询层阻止上传。
- 软删除不物理删除索引；恢复物品后按既有状态/requested 规则决定是否继续。
- 补充 DAO/查询行为验证；无设备时明确 `NOT VERIFIED`。

### DATA-5（IMPORTANT）视觉搜索不得使用已不属于当前物品的索引路径

- `VisualSearchEngine` 或 DAO 查询必须校验 `image_path` 仍属于当前 `ItemEntity.imagePaths`。
- 照片移除失败、进程中断或并发写入时，不得返回 stale 路径给 UI。
- 增加纯逻辑或查询级回归测试。

### DATA-6（OPTIONAL）图片复制中断残片清理

- 图片目标文件在复制前/失败后也必须纳入清理范围，避免半写文件残留。
- 不得因清理失败覆盖原始导入错误。
