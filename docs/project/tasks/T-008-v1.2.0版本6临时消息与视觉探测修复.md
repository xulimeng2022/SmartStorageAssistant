# T-008 v1.2.0（versionCode 6）临时消息本地化 + 视觉探测修复

## 目标

- Bug 1：语言切换后 Toast / Snackbar / Dialog 等临时 UI 消息仍按旧 Locale 显示，改为「类型化消息 + 显示层解析」。
- Bug 2：DeepSeek V4.1 Flash（`deepseek-flash`）视觉能力探测始终失败，修正线程、错误分类与负缓存问题，保留旧 alias 兼容。

## 范围

- 涉及：M03 AI 解析与远程 LLM、M05 备份与恢复、M06 偏好与配置存储、M11 设置外观与主题，以及 presentation 层统一消息与三语言资源。
- 不涉及：向量库、CLIP、全相册扫描、Bounding Box、原生非 OpenAI 协议适配；不改动隐私语义、本地索引与 Top-5 手动复核流程。

## 根因与修复

### Bug 1 临时消息语言错乱

- 根因：语言切换只重建 Activity，而 ViewModel / LlmClient 注入的是 `@ApplicationContext`，其 Resources 仍是旧语言；这些位置又用 `getString()` 提前缓存文本或直接 Toast。
- 修复：新增 `UiMessage`（资源 ID + 参数，可组合），`SettingsViewModel`、`AddItemViewModel`、`ItemDetailViewModel`、`AboutViewModel` 的消息改为资源 ID / 事件流，`LlmClient` 只向上抛类型化错误，由显示层用界面 Context 解析。

### Bug 2 视觉探测失败

- 根因：`VisionAnalyzer.probe/analyze/verify` 在 `viewModelScope` 主线程直接执行同步 OkHttp 调用；400/404 一律映射为模型不支持；能力探测失败结果被持久化，旧负结果持续阻断用户开启。
- 修复：网络段统一 `withContext(Dispatchers.IO)`；探测结果细分为 MODEL_UNSUPPORTED / AUTH / QUOTA / RATE_LIMIT / NETWORK / TIMEOUT / SERVER / BAD_REQUEST / MODEL_NOT_FOUND / RESPONSE_PARSE / INCOMPATIBLE / UNKNOWN；仅服务端明确拒绝图片输入才算不支持；能力指纹纳入 Provider + 归一化 Base URL + Model + 协议版本 + 探针版本；只持久化 SUPPORTED，失败仅在本次会话展示；保存 AI 配置或切换模式时使旧能力失效。
