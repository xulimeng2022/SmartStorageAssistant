## Required Fixes

### UI-1（BLOCKER）移除 SettingsScreen 重复对话框

- 当前 `SettingsScreen` 中检查更新三态、删除第一步、删除第二步、执行中对话框各存在两套组合。
- 只保留一套；确保任一状态只组合一个 `AlertDialog`。
- 静态验收：`SettingsScreen` 内 `updateResult?.let`、`showDeleteDataDialog`、`showDeleteDataFinalDialog`、`resetBusy` 的状态渲染入口各为 1。

### UI-2（IMPORTANT）修正单图索引按钮语义

- `NOT_CREATED` / `FAILED`：创建或重试。
- `OUTDATED`：重新请求刷新，不得执行删除。
- `SUCCESS`：允许删除索引，删除只影响派生索引，不影响照片。
- `PENDING` / `PROCESSING`：不得无提示删除或取消；按钮应禁用或明确只展示状态。
- 不得再用单一 `false` 分支吞掉所有失败；至少保留现有用户提示，具体错误映射若需要跨模块 contract 变更则报告 Coordinator。

### UI-3（BLOCKER）关闭图片理解后停止 Top-5 后续上传

- 用户关闭图片理解后，Top-5 复核循环不得继续对剩余候选调用 `visionAnalyzer.verify()`。
- 在每张候选发送前检查 `ImageUnderstandingRepository.state.value`；关闭或 capability 非 `SUPPORTED` 时立即停止，并保留已获得的本地结果。
- 已发出的单次请求无法撤回，但不得继续发送后续请求。
- 若需要取消正在运行的复核 Job，只能修改 UI-owned `HomeViewModel`。

### UI-4（IMPORTANT）邮箱兜底本地化与语义

- 无邮件应用时的复制兜底不得用 `@ApplicationContext.getString()` 直接解析 UI 文案。
- Toast/提示必须走显示层 Context 或既有 `UiMessage` 解析机制。
- 文案改为“邮箱已复制，可粘贴到邮件服务”一类语义，三语言同步。
- `ACTION_SENDTO` 成功路径保持打开邮件应用；无邮件应用时复制仍成功。
