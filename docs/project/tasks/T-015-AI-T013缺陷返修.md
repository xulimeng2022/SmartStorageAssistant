### AI-1（BLOCKER）缺失图片文件不得造成 Worker 死循环

- 当前路径：文件不存在时直接 `markFailed`，但该方法只接受 `PROCESSING`；`PENDING/OUTDATED` 行不会被更新并会被反复取出。
- 不得修改 Data DAO contract；在 AI-owned Worker 中使用现有公开 repository 方法保证该行先进入可标记失败的合法状态，或采用等价的纯 AI 侧安全路径。
- 任何取得队列行后的分支都必须保证状态最终离开 `getQueued()` 返回集合，或在明确并发失败时安全退出本轮。
- 增加可执行的回归测试；若 `CoroutineWorker` 缺少 JVM seam，可抽取纯控制流函数并直接测试“文件缺失只会处理一次且不会再次返回队列”。

### AI-2（IMPORTANT）LocalDescriptionParser 不得把第二件物品并入首件地点

- 修复 `isLocationContinuation` / 地点补语判断，至少覆盖：
  - `充电器放在柜子里，抽屉里的钥匙` 应解析为两条物品。
  - 已有点题例不得回归。
- 对长度不超过 12、含地点名词但带独立物品名词的后续子句，不得无条件视为地点补语。
- 先添加失败测试，再最小实现。

### AI-3（OPTIONAL）恢复 CancellationException 语义

- `VisionAnalyzer.analyze` / `verify` 使用 `runCatching` 时不得把 `CancellationException` 转换为普通失败。

- 补充可执行回归测试；若 Android Bitmap 依赖限制测试，至少覆盖纯解析/协程边界。
