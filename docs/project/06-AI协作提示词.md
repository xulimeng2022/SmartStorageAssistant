# AI 协作提示词（适配本项目）

> 用途：新会话 / 新模块 / Bug 排查 / 任务完成回写。发送前把【占位内容】替换为实际值。
> 本项目知识库路径：`docs/project/`；原始通用模板见 `../reference/ai-project-template/06-AI新项目启动提示词.md`。

## A. 让 AI 理解本项目后再开工（新会话必读）

~~~text
你是「智能收纳助手」（Android/Kotlin/Compose，仓库根目录）的开发协作者。先只读以下文档再回答我：
1. AGENTS.md
2. docs/project/00-项目索引.md
3. docs/project/01-需求与范围确认.md
4. docs/project/02-系统架构.md
5. 任务对应模块文档 docs/project/modules/Mxx-*.md
6. docs/project/04-任务与验收清单.md 与当前任务卡（docs/project/tasks/，如有）
然后回答：项目是什么、当前版本、本任务属于哪个模块、该模块负责/不负责什么、本任务要改变哪个可观察行为、哪些不能改、应如何测试、完成后哪些结论要回写。
要求：事实先从代码/配置验证；不明确就标「待确认」，不要猜。
~~~

## B. 开启一个模块开发对话

~~~text
你现在只负责模块【模块名】中的任务【T-编号：任务名称】。
请只阅读：docs/project/00 索引、01 需求、02 架构、modules/Mxx 模块文档、tasks/ 任务卡、相关代码与现有测试。

任务目标：【行为】
不做范围：【明确排除】
验收标准：【来自 01 的 A-编号或自述】

工作规则：
1. 需求/模块边界/验收有歧义 → 指出具体问题并停止猜测。
2. 适合自动化的行为 → 先写一个会失败的测试描述目标行为；测试 seam 已明确（测试目标 / 模块 / 验收标准已给定）时直接执行，seam 影响模块接口 / 架构时先与用户确认。
3. 再最小实现使测试通过，不顺手重构无关代码。
4. 运行受影响测试（`:app:testDebugUnitTest`），报告结果与改动文件。
5. 有长期价值的稳定结论 → 建议回写模块文档；临时日志不写入长期文档。
~~~

## C. 让 AI 排查一个 Bug

~~~text
你现在只排查【模块】中的 Bug：【现象】。
边界：关联模块文档 docs/project/modules/Mxx-*.md；预期行为；实际行为；最小复现步骤；已有测试/错误信息；本次不改动范围。
请按顺序输出：
1. 从当前模块、调用链与已有测试可确认的事实。
2. 最可能的根因与证据；无法确认时说明需要什么信息。
3. 一个最小修复方案与要新增/调整的失败测试。
4. 不要扩大到其它模块或加入无依据兜底。
~~~

## D. 任务完成后的知识库回写

~~~text
请根据已完成任务【T-编号】和验证结果，区分：
- 应写入长期知识库的稳定事实：模块边界、接口契约、状态定义、架构决策、可复用待办 → 建议更新 docs/project/modules/ 对应文档、02 架构、04 Todo。
- 不应写入长期知识库的短期信息：日志、命令输出、真实数据、凭据、截图、一次性回执。
只输出建议更新的文件、段落与 Markdown 草案；没有长期结论就明确写「无需回写」。
~~~

> 注意：本项目仓库规则（AGENTS.md 与全局规范）要求中文交流、代码注释中文、敏感信息（API Key/签名密码）绝不写入文档或提交。
