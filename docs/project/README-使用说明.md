# docs/project 使用说明（新人 / 新 Agent 入口）

> 本目录是「智能收纳助手」的项目专属知识库：只放项目事实与协作流程。
> 原始通用模板（保持原样）在 `../reference/ai-project-template/`；两者职责分离，不要互相混填。

## 新人 / 新 Agent 如何进入项目

```text
AGENTS.md（协作规则 + 本知识库指针）
  ↓
00-项目索引（项目是什么、模块导航、文档入口）
  ↓
PROJECT_STATUS（当前版本 / 阶段 / 测试 / lint / 待验收，按需）
  ↓
01-需求与范围（做什么 / 不做什么 / 如何验收）
  ↓
02-系统架构（分层与模块边界）
  ↓
modules/Mxx-当前任务对应模块（负责什么 / 不负责什么 / 代码位置）
  ↓
tasks/ 当前任务卡（如有）
  ↓
相关代码与测试（app/src/...）
```

原则：按需读取，不要求每次读完所有文档；项目事实先从代码/配置验证；不确定标「待确认」。

## 日常开发的三级流程

| 级别 | 示例 | 流程 |
| --- | --- | --- |
| Level 1 小修改 | 文案/颜色/Padding/图标/局部低风险 | Todo → 修改 → 验证 |
| Level 2 普通功能/Bug | 搜索、AI 错误处理、批量识别问题 | 模块 → Todo → 任务卡 → 失败测试(适用时) → 实现 → 验证 → 验收 → 回写 |
| Level 3 大功能/架构变化 | 新模块、数据库迁移、核心架构 | 需求确认 → 架构 → 模块设计 → Todo → 拆分 → 任务卡 → 实现 → 测试 → 验收 → 回写 |

任务卡模板见 [05-单任务卡-TDD](05-单任务卡-TDD.md)，登记与状态见 [04-任务与验收清单](04-任务与验收清单.md)。

## Bug 处理流程

```text
确认现象 → 最小复现 → 定位模块 → 任务卡 → 失败测试 → 最小修复 → 验证（受影响测试）
```

## 任务完成流程

```text
受影响测试通过 → 验收 → 更新 04 Todo → 长期结论回写模块/架构 → 结束
```

| --- | --- |

## 写入纪律（重要）
- 长期知识（模块边界、接口契约、状态定义、数据模型、稳定业务规则、架构决策、环境/构建/发布规则）→ 写入对应长期文档。
- 短期信息（终端输出、完整日志、一次性错误、调试过程、截图、临时文件）→ 只留在任务卡/Git/Issue，不写入长期文档。
- 敏感信息（API Key、签名密码、token、local.properties 值、真实账号）→ 任何文档与提交都禁止出现。
- 无法确认 → 标「待确认」，并在 00 与最终交付报告集中汇总；宁可留待确认，不写看似完整的猜测。
