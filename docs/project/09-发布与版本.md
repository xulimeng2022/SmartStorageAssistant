## 版本规则
- 日常开发（功能 / 修复 / 重构 / UI / 资源 / 配置 / 依赖变更）不得自动递增版本号；只有 Release 阶段或用户明确要求时才更新，见根目录 `AGENTS.md`「版本号规则」与 `PROJECT_STATUS.md`。
- 每次发版 versionCode 必须大于上一版（Android 升级判定）。

## 构建
| 类型 | 命令 | 产物 |
| --- | --- | --- |
| Debug | `.\gradlew.bat :app:assembleDebug` | `app\build\outputs\apk\debug\app-debug.apk` |
| Release | `.\gradlew.bat :app:assembleRelease` | `app\build\outputs\apk\release\app-release.apk` |

- Release 开启 R8 混淆与资源压缩（`isMinifyEnabled` / `isShrinkResources`），规则在 `app/proguard-rules.pro`。

## 签名（只记录位置与规则，不记录值）
- 签名配置在 `app/build.gradle.kts` 的 release 构建类型，从根目录 `local.properties` 读取 `KEYSTORE_FILE / KEYSTORE_PASSWORD / KEY_ALIAS / KEY_PASSWORD`；未配置则产出未签名 APK。
- 密钥库文件（`*.jks`/`*.keystore`）已被 `.gitignore` 忽略，严禁提交；`local.properties` 同样不入库。
- 密钥丢失后无法对已发布 App 升级签名，需妥善备份（见 RELEASE_GUIDE.md）。

## Release 流程（GitHub Releases）
1. 更新 `versionName/versionCode`；构建 Release APK；留存 `mapping.txt`。
2. 归档混淆映射到 `release/<版本>/mapping.txt`（仓库现有 v1.0.0/v1.0.1/v1.1.0）。
3. 在 `https://github.com/xulimeng2022/SmartStorageAssistant` 创建 Release（Tag 形如 `v1.1.0`），上传 APK。
4. 更新 README「更新记录」。
- 分支习惯：历史经 `codex/release-vX.Y.Z` 分支发布后并入 main（v1.0.0、v1.1.0 均如此）。
